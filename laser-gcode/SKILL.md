# 激光图形转 G 代码

把平面图形变成可上机运行的 GRBL 激光 G 代码，并给出匹配材料与机器的功率/速度参数。

## 何时使用

凡是涉及「激光雕刻/切割」「图形转 G 代码」「激光功率速度」「在 X 材料上激光加工」的需求都应触发。
典型信号：用户贴了轮廓图/截图/照片、给了 SVG、列了一串坐标点、问「这个图形要多少功率多快速度」，
或提到 GRBL / LightBurn / 雕刻机 / 激光模组。

## 第 0 步：先确认机器与环境

30 秒的确认能省掉一整块废料。能查就问，问不到就用默认值并在交付时说明假设——
但**额定功率、材料、目标尺寸**这三项尽量确认。

| 要确认 | 默认 | 为什么重要 |
|---|---|---|
| 图形 | 必填 | 顶点坐标（归一化 0–100 网格）、SVG 路径，或 PNG/JPEG（用交互页面矢量化） |
| 激光器额定功率 | 10W | 决定材料库档位 → 决定 `S` 值 |
| 材料 | `plywood_3mm` | 见 `references/materials.json` 的 key，或让脚本 `--list-materials` |
| 作业类型 | `cut` | `cut` 切穿 / `engrave` 描边 / `fill` 内部填充 |
| 目标尺寸 mm | `100 100` | `--target-size`，最终加工尺寸 |
| 机床床身行程 | 不限 | 用 `--bed W H` 让脚本校验刀路是否超行程 |
| `$30` / `$32` | 1000 / 未确认 | `S` 的上限；`$32=1` 是激光模式，没开激光不会调制 |
| 输入坐标原点 | `top-left` | 图形 Y 向下（图像/屏幕）还是 Y 向上（CAD） |
| 输出原点 | `bottom-left` | 标准 CNC 是左下、Y 向上 |

问不到床身/原点时，直接用默认值，并在交付时写清「假设图形坐标原点在左上、机床原点在左下」。

## 安全红线（每次交付都要讲，不要省）

1. **人不能离开机器**；旁边备好灭火手段。激光加工是明火级别的火灾风险，纸板/MDF/毛毡几秒就能引燃。
2. **护目镜 + 外罩，不要直视光斑**（含工件反射的散射光）。
3. **禁止加工**：PVC/乙烯基/仿皮、ABS、聚碳酸酯、玻纤/碳纤维、含铬鞣制皮革、未知塑料——
   会释放氯气、氰化物、六价铬等剧毒气体。
4. **必须排烟通风**：MDF、皮革、亚克力、毛毡、织物；排到室外，不是「开窗」。
5. **切割开气泵**；每次换材料重新对焦（焦距偏差是参数失准的头号原因）。
6. **参数只是起点**：先在同批废料上做测试网格，再正式加工。

完整版（含材料毒性表与话术）见 `references/safety.md`。

## 核心机制（理解这两点，输出才不会错）

### 1. `S` 是占空比，不是光功率

`S = 功率% × $30`（通常 `$30=1000`），真实光功率 = `S / $30 × 激光器额定功率`。
所以**同一材料在不同功率机器上需要不同的 `S`**：10W 机器切 3mm 椴木要 `S1000`（满功率、两遍），
40W 机器只需 `S700`（70%、一遍）。

材料库按**激光器功率档位**（5/10/20/40W）存「功率% + 速度 + 遍数」，脚本按 `--laser-w` 选档并换算。
这就是本 skill 的核心价值：一份表适配所有机器。
当 `--laser-w` 落在档位之外（如 60W、或 5W 用只有 10W 起的材料）时脚本会 `[warn]` 提醒参数已偏离表格意图——
**这类告警必须转述给用户**，不要吞掉。

### 2. 坐标系：源坐标系（frame）→ 目标尺寸 → Y 翻转

- 坐标先落在某个**源坐标系**里：顶点默认是 0–100 网格；SVG 用 `viewBox`（没有则用 `width/height`，再没有才用图形包围盒）。
- 脚本把源坐标系映射到 `--target-size`，再按输入/输出原点决定是否翻转 Y。
- 顶点不在 0–100 区间时用 `--normalize auto`（按图形包围盒铺满）或 `--frame x0 y0 w h`（显式声明源坐标系）。
- 目标尺寸宽高比与图形不一致时，`--fit stretch`（默认）会独立缩放 X/Y（圆会变椭圆）并 `[warn]`；
  想保持比例就加 `--fit contain`。

「图形倒过来了 / 小得看不见 / 大了十倍」几乎都是 frame 或原点的问题。
先跑 `--check` 看报告里的 `frame`、`bbox`，比对着机器猜要快得多。

## 工作流

### 第 1 步：生成（用脚本，不要手写 G 代码）

脚本是确定性的，封装了坐标变换、档位换算、曲线展平、填充走位与边界校验——优先用它。

```bash
python3 scripts/generate_gcode.py \
  --svg part.svg \
  --job cut --material plywood_3mm --laser-w 10 \
  --target-size 80 80 --bed 300 300 \
  --output part_cut.gcode
```

顶点输入用 `--vertices "50,2 57,18 ..."`（也接受 `50 2;57 18` 或 JSON 数组 `[[50,2],[57,18]]`）。

常用参数：

| 参数 | 说明 |
|---|---|
| `--job cut\|engrave\|fill` | 作业类型 |
| `--material` / `--laser-w` | 材料 key 与激光器额定功率 |
| `--target-size W H` | 最终加工尺寸（mm） |
| `--offset X Y` | 从工件原点平移（Y 翻转之后施加，正值向上/向右） |
| `--fit stretch\|contain` | 填满目标框 / 保持宽高比居中 |
| `--normalize none\|auto` · `--frame X0 Y0 W H` | 源坐标系处理 |
| `--power` / `--feed` / `--passes` | 覆盖材料库推荐值 |
| `--hatch-spacing` / `--hatch-angle` | 填充线距（mm）与角度 |
| `--fill-outline none\|before\|after` | 填充前后补一圈描边（边缘更干净） |
| `--grbl-max-s` | 与机床 `$30` 一致，默认 1000 |
| `--bed W H` | 床身尺寸，用于越界校验 |
| `--laser-mode m3\|m4` | 默认 `m3` 恒定功率；`m4` 为 GRBL 动态功率（需 `$32=1`） |
| `--check` | 只输出参数与几何报告，不写 G 代码 |
| `--list-materials` | 列出材料库 key、档位、是否可切 |
| `--config job.json` | 一次性传所有参数（下划线键名，优先级高于命令行） |

### 第 2 步：自检（生成后必做，别直接丢给用户）

1. 看 stderr 的 `[warn]`：刀路越界、超床身、档位越界、宽高比、SVG 元素被跳过——逐条判断是否需要改参数。
2. 看摘要里的 `bbox`：应落在目标尺寸内；`est` 耗时是否合理（填充过密会很久）。
3. 需要先看参数再决定时，加 `--check`（不写文件，只出报告）。
4. 只要出现 `[error]`，脚本会以退出码 2 结束——按提示修正输入，不要硬改生成的 G 代码。

### 第 3 步：交付

向用户交付时**必须**包含四件事：

1. **G 代码文件路径**
2. **参数摘要**：材料、额定功率、选用的档位、换算后的 `S`、进给速度、遍数、目标尺寸、包围盒、预计耗时
3. **安全提示**：按材料说清通风/气泵/护目/测试网格（见「安全红线」）
4. **所有 `[warn]` 的转述**：脚本已经替你做了体检，别把体检报告丢掉

## 图片输入：交互式矢量化工作台

用户给的是 PNG/JPEG（截图、照片、logo 位图）时，**不要再让他自己去找 SVG**。
随 skill 附带的单文件页面先把位图变成矢量，再下载 SVG 喂脚本，或直接在页面里出 G 代码：

```bash
bash scripts/open_vectorizer.sh      # 等价于用浏览器打开 assets/vectorizer.html
```

页面是纯前端离线单文件（图片不上传），流程：取色/阈值 → 二值掩膜 → 像素边界追踪闭合轮廓（含孔洞）
→ RDP 简化 + 可选平滑 → 裁留白并映射到目标 mm → 切割/描边，或 hatch 填充（逐段 `M5 → G0 → M3 S → G1`）
→ 材料库选档、`S` 换算、床身校验、耗时估计 → 下载 `.gcode` / `.svg`。

要点：

- 页面材料表由 `references/materials.json` 注入；**改完 JSON 必须**跑
  `python3 scripts/sync_materials.py`（加 `--check` 只校验，不同步就退出码 1）。
- 导出的 SVG 是毫米坐标、`viewBox 0 0 W H`，可直接 `--svg` 喂给脚本；
  实测同一图形两条链路的 bbox、燃烧长度、`S`/`F`/遍数完全一致，可用来交叉复核。
- 适合 logo、剪影、线稿；**照片**会碎成大量轮廓，先做提亮/去背景。
- 位图矢量化只给二值轮廓：不保留灰度，也不做网点/抖动；要照片级灰度雕刻得换工具。

## SVG 支持范围

| 类别 | 支持 | 不支持时的行为 |
|---|---|---|
| 元素 | `path` `polygon` `polyline` `rect` `circle` `ellipse` `line` | `<text>`/`<image>`/`<use>` 会 `[warn]` 并跳过（先在矢量软件里「文字转曲」） |
| 路径命令 | `M L H V C S Q T A Z`（含相对形式） | 其它字符一律 `[error]` 报出具体位置（不再静默截断图形） |
| 变换 | `<g transform>` 的 `matrix` `translate` `scale` `rotate` `skewX` `skewY`，支持嵌套 | 无法解析的变换直接 `[error]` |
| 框架 | 根 `viewBox` → 否则 `width/height`（自动换算 mm/cm/in/pt/px）→ 否则图形包围盒（`[warn]`） | 可用 `--frame` 显式覆盖 |
| 裁剪/遮罩 | 不处理 | `clipPath`/`mask` 被忽略，按未裁剪形状输出 |

曲线在映射到 mm 之后才按 `--flatten-tol`（默认 0.02mm 弦高误差）自适应展平，
既不会像固定步数那样在图大时切出多边形，也不会在图小时浪费点数。

## 填充扫描（hatch）

- **逐段走位**：每一个燃烧段都是 `M5 → G0 起点 → M3 S… → G1 终点`，
  所以绝不会带着激光横穿镂空/孔洞（凹形、多岛屿、带孔图形都安全）。
- 扫描线用牛耕式（boustrophedon）往返，`--hatch-angle` 可换方向；
  多个多边形的交点在每条扫描线上合并后按奇偶配对，带孔图形会被正确跳过孔洞。
- **间距**：木材/亚克力雕刻常用 0.1–0.3mm；越密越慢，先用 `--check` 看耗时再决定。
- 线距 ≤ 0 会立刻 `[error]`（不会挂死）。
- 填充默认复用该档位的 `engrave` 参数；材料库的档位里若显式写了 `fill` 块，则以 `fill` 为准。
- `--passes` 会真正重复整轮填充（用来加深）。

## 完整案例：枫叶切割（精简）

用户给出 22 个归一化顶点（原点左上、Y 向下），10W 二极管切 3mm 椴木，80mm 见方：

```bash
python3 scripts/generate_gcode.py \
  --vertices "50,2 57,18 71,16 62,35 98,43 78,62 93,68 65,75 68,85 53,80 53,98 47,98 47,80 32,85 35,75 7,68 22,62 2,43 38,35 29,16 43,18 50,2" \
  --job cut --material plywood_3mm --laser-w 10 --target-size 80 80 \
  --output maple_leaf_cut.gcode
```

摘要：`S=1000 feed=500 passes=2`，包围盒 `76.8 × 76.8 mm`，预计 1.4 分钟。

要点：①顶部尖角 `(50,2)` 被翻转到 `Y=78.4`，叶尖朝上；②首尾重复的顶点会自动去重，不产生零长度移动；
③每遍开始前 `M5 → G0 → M3 S` 重新出光，开放路径也能正确多遍加工。

完整 G 代码输出、40W 机器对照参数、SVG 版本命令见 `references/example-maple-leaf.md`。

## 材料参数库

`references/materials.json` 是脚本的数据源，`references/materials.md` 是人类可读说明。
先跑 `--list-materials` 看有哪些 key 与档位，比翻 JSON 快。

- 数值全部是**起点**：批次、焦距、透镜、气泵、机器功率都会影响结果，必须实测微调。
- `cut.passes = 0` 表示该材料不能切割（阳极氧化铝、板岩只能雕刻/标记）。
- 新增材料只需在 `materials.json` 加一个 key，按档位填 `cut`/`engrave`（可选 `fill`）；
  脚本启动时会校验 schema，字段缺失或功率越界会直接报错。
- 改完材料库记得 `python3 scripts/sync_materials.py`，否则交互页面还停在旧参数上。

## 失败处理与边界

- 顶点少于 3 个 → `[error]` 提示补全图形（JSON 数组输入同样校验）。
- 材料不支持切割（`cut.passes=0`）→ `[error]`，改用 `--job engrave`。
- `--hatch-spacing` ≤ 0、扫描线数超限 → `[error]`，不会死循环。
- **二极管激光不能切金属、不能切透明亚克力**——明确告知用户限制，不要硬生成注定失败的 G 代码。
- SVG 里没有可用图形 → `[error]` 并列出支持的标签；含 `<text>` 会 `[warn]` 说明已跳过。
- 用户给的是**图片**而非坐标/SVG → 用 `assets/vectorizer.html` 矢量化（见「图片输入」一节），
  不要让他自己去转 SVG；照片类素材先说明二值轮廓的局限。
- 不要手工编辑脚本生成的 G 代码；需要改动就改输入参数重新生成。

## 排障

常见现象与处置见 `references/troubleshooting.md`，最快的四条：

| 现象 | 处置 |
|---|---|
| 完全不出光 | `$$` 检查 `$32`，发 `$32=1` 打开激光模式 |
| 刻出来倒置/镜像 | 输入/输出原点设错：`--input-origin` / `--output-origin` |
| 尺寸大了十倍或小得看不见 | 源坐标系不对：`--frame` 或 `--normalize auto` |
| 切不透 / 边缘焦黑 | 先 `--check` 看实际光功率，再调 `--power`/`--feed`/`--passes`，并检查焦距与气泵 |

## 与用户的沟通

- 术语要解释：`S` 是激光强度档位（0–1000），`F` 是移动速度（毫米/分钟），`$30` 是 S 的上限。
- 给出参数时说明**为什么**（如「3mm 椴木在 10W 机器上需满功率切两遍」），让用户理解而不是盲从。
- 主动建议先做测试网格（5×5 的功率×速度矩阵），这是激光加工的标准做法，能省下大量返工。
- 有 `[warn]` 就如实说；参数失准会烧穿或引燃材料，提前提醒能避免事故。
